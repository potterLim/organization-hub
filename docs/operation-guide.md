# 운영 가이드

Organization Hub는 팀 이름·팀별 직책·자료 위치·일정·할 일·결재 경로를 관리자 화면에서 설정하는 조직 운영 도구입니다.

## 첫 설정 순서

1. 초기 시스템 관리자 계정으로 로그인합니다.
2. `/admin/google`에서 운영 Google 계정을 연결합니다.
3. `/admin/teams`에서 실제 조직의 팀을 만듭니다.
4. `/admin/positions`에서 팀별 직책을 만들고 직책별 권한 범위를 설정합니다.
5. `/admin/users`에서 사용자를 만들고 팀과 직책을 배정합니다.
6. `/admin/google` 또는 `/admin/settings`에서 Drive 폴더·Calendar·Google Tasks 목록을 연결합니다.
7. `/admin/approval-workflows`에서 결재 경로를 설정합니다.
8. 권한이 다른 사용자 계정으로 로그인해 메뉴·자료·일정·할 일·결재 권한을 확인합니다.

## 시스템 관리자와 관리팀

시스템 관리자는 제품 설정과 보안 운영을 담당하는 최고 권한 계정입니다.  
초기 설정·팀 생성·직책과 권한 부여·Google 연결·시스템 설정은 시스템 관리자가 담당합니다.

관리팀은 실제 조직 운영을 담당하는 일반 팀입니다.  
관리팀 이름·구성원·직책·권한도 다른 팀과 마찬가지로 관리자 화면에서 관리합니다.  
관리팀 자료는 별도 자료 영역으로 제공되며 접근 가능 여부는 관리자가 부여한 직책 권한과 메뉴 설정에 따라 결정됩니다.

시스템 관리자 계정은 업무 결재자나 일반 실무 계정으로 사용하지 않는 것을 권장합니다. 실제 업무 흐름은 관리팀과 각 팀의 직책·권한·결재 워크플로로 구성합니다.

## 팀과 직책

팀은 조직 단위입니다.  
관리자는 팀 이름·정렬 순서·활성 상태·팀 자료 폴더·결재 완료 폴더·팀 Calendar·팀 Google Tasks 목록을 관리합니다.

직책은 팀마다 따로 만듭니다. 같은 이름을 여러 팀에서 쓸 수도 있고 팀마다 완전히 다른 직책 이름을 쓸 수도 있습니다.

직책에는 다음 권한을 줄 수 있습니다.

- 자료 조회·업로드·수정·삭제
- 일정 조회·생성·수정·삭제
- 할 일 조회·생성·수정·삭제
- 결재 요청·결재 승인·최종 승인·결재 기록 조회
- 사용자·팀·직책·권한·결재 경로·Google 연결·메뉴·시스템 설정 관리

권한 범위는 모든 팀·소속 팀·소속 팀과 하위 팀·지정 팀·생성자 기준으로 나눕니다.  
현재 버전은 팀 계층을 별도 데이터로 관리하지 않으므로 `소속 팀과 하위 팀` 범위는 소속 팀 범위와 동일하게 적용됩니다.

## 사용자 운영

사용자는 직접 가입하지 않습니다. 시스템 관리자나 사용자 관리 권한이 있는 직책이 관리자 화면에서 계정을 만듭니다.

일반 사용자 계정에는 팀과 직책이 필요합니다. 비밀번호는 평문으로 저장하지 않으며 운영자는 기존 비밀번호를 볼 수 없고 새 비밀번호로 초기화만 할 수 있습니다.

팀이나 직책을 바꾸면 사용자의 메뉴와 작업 권한도 새 권한 기준으로 갱신됩니다. 권한 변경 후에는 해당 사용자가 실제로 접근 가능한 메뉴와 서버 작업을 확인합니다.

## 자료 운영

자료 위치는 관리자 화면에서 Google Drive 폴더를 선택해 연결합니다.

기본적으로 다음 종류의 위치를 사용할 수 있습니다.

- 관리팀 자료
- 공통 자료
- 외부 공유 자료
- 업무 지원 자료
- 책임자 자료
- 팀별 자료
- 팀별 결재 완료 자료

관리팀 자료와 팀별 자료 및 결재 완료 자료는 팀 관리에서 각 팀에 연결합니다. 공통 자료나 외부 공유 자료는 시스템 설정 또는 Google 연결 화면에서 연결합니다.

시스템 설정의 Drive 탭에서는 공지 파일과 업무 기준 파일도 선택할 수 있습니다.  
업무 기준 파일은 Drive에 보관하는 참고 자료를 연결하는 용도이며, 업무 기준 화면의 카드 내용은 화면에서 직접 편집한 데이터로 표시됩니다.

파일 업로드와 결재 완료 자료 저장 시 같은 위치에 같은 이름의 파일이 있으면 기존 파일 교체 또는 새 파일로 추가를 선택합니다.  
새 파일로 추가하면 `파일명 (2).확장자`처럼 사용할 수 있는 이름을 제안합니다.

권한이 없는 사용자가 원본 ID를 바꿔 접근할 수 없도록 서버에서 파일 권한을 다시 확인합니다.

## 일정과 할 일

일정은 Google Calendar를 사용하고 할 일은 Google Tasks 목록을 사용합니다.  
조직 공용·책임자·팀별 Calendar와 목록을 연결할 수 있으며 실제 조회와 수정 가능 여부는 직책 권한과 연결된 대상 기준으로 결정됩니다.

시스템 설정에서는 일정과 할 일 화면에 작성자 정보를 표시할지 정할 수 있습니다.  
할 일은 마감 기한을 둘 수도 있고 비워 둘 수도 있습니다. 마감 기한은 사용자의 브라우저 시간대로 입력하고 화면에 표시합니다.  
일정 삭제 기록, 일정과 할 일 작성자 정보, 자료 업로드 기록은 운영 추적을 위해 남깁니다.

## 결재 경로

결재 경로는 관리자 화면에서 설정합니다.

워크플로에는 요청 팀 조건·요청 직책 조건·단계 수·각 단계의 결재자 선택 방식을 지정합니다.  
요청 팀과 요청 직책은 비워 둘 수 있으며 비어 있는 조건은 모든 요청자에게 적용됩니다.

결재자는 특정 사용자·특정 직책·요청자 팀의 특정 직책·지정 팀의 특정 직책·특정 권한 보유자 방식으로 찾을 수 있습니다.

같은 요청에 여러 결재 경로가 맞으면 `팀+직책` 조건 경로, `팀` 조건 경로, `직책` 조건 경로, `전체` 경로 순서로 확인합니다.  
같은 수준의 경로가 여러 개면 화면에서 위에 있는 경로가 먼저 선택됩니다.

결재 경로가 특정 사용자나 직책을 가리키더라도 실제 결재자는 해당 단계에 필요한 결재 승인 권한을 함께 가져야 합니다. 마지막 단계는 최종 승인 권한을 기준으로 확인합니다.

검토자가 코멘트 없이 승인하면 기본 코멘트는 `승인`으로 남습니다.  
최종 결재권자가 코멘트 없이 승인하면 기본 코멘트는 `결재`로 남습니다. 반려는 사유 입력이 필요합니다.

새 운영 환경에서는 최소 하나 이상의 결재 워크플로를 명시적으로 만들고 요청자와 결재자 계정으로 실제 요청과 승인 흐름을 확인합니다.

## 메뉴와 업무 기준

메뉴 보이기 설정에서는 왼쪽 메뉴의 섹션, 메뉴 이름, 표시 대상, 팀 표시 범위를 관리합니다.  
섹션과 메뉴 순서는 드래그해서 정하며 시스템 관리자는 관리 목적상 모든 활성 메뉴를 볼 수 있습니다.

일반 사용자는 메뉴 표시 조건과 직책 권한을 모두 만족해야 메뉴를 볼 수 있습니다.  
메뉴가 숨겨져도 URL 직접 접근이 가능하므로 서버는 각 요청마다 권한을 다시 확인합니다.

업무 기준 화면은 0개부터 9개까지 카드로 구성할 수 있습니다.  
시스템 설정 권한이 있는 사용자는 화면에서 카드 수, 제목, 내용, 순서를 직접 편집하고 저장 전 미리보기를 확인할 수 있습니다.

## 운영 점검

- 새 팀을 만들고 팀별 자료·Calendar·Google Tasks 목록을 연결했는가
- 관리팀 자료와 일반 팀 자료가 서로 다른 권한으로 보호되는가
- 각 팀에 필요한 직책과 권한 범위를 만들었는가
- 일반 사용자가 다른 팀 자료를 보거나 수정할 수 없는가
- 관리자 권한이 없는 계정이 관리자 메뉴에 접근할 수 없는가
- 메뉴 섹션과 메뉴 표시 범위가 의도한 사용자에게만 보이는가
- 업무 기준 카드가 사용자 화면에 자연스럽게 표시되는가
- 결재 요청자가 의도한 결재 경로를 따라가는가
- 각 결재 단계 후보자가 실제 결재 승인 또는 최종 승인 권한을 갖고 있는가
- Google 연결 진단이 정상인가
- 운영 데이터 볼륨과 환경 변수 백업이 최신인가
