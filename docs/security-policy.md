# 보안 정책

Organization Hub의 핵심 보안 목표는 사용자가 자신에게 부여된 팀·직책·권한 범위 안에서만 자료·일정·할 일·결재 기록을 보거나 변경하게 하는 것입니다.

## 인증

- 직접 회원가입은 허용하지 않습니다.
- 계정은 관리자 화면에서 생성합니다.
- 비밀번호는 해시로 저장합니다.
- 비활성 사용자는 로그인할 수 없습니다.
- 운영 환경에서는 HTTPS가 필수입니다.

## 권한 검증

권한 검사는 화면 표시와 별개로 서버에서 다시 수행합니다.

Calendar와 Tasks의 생성·수정·삭제는 작업별 권한을 각각 확인합니다. Tasks의 완료·재개·정렬에는 수정 권한을 적용합니다. 생성 권한만으로 기존 항목을 수정하거나 삭제할 수 없습니다.

인증 쿠키는 HTTP 요청마다 현재 계정·직책·팀의 활성 상태를 확인합니다. 열린 Blazor 연결에서도 서버 입력 작업을 실행하기 전에 최신 메뉴 접근 권한을 검사하며, 화면은 2초 간격으로 권한 변경을 확인합니다. 계정이 비활성화되면 로그인 화면으로, 현재 화면의 권한이 회수되면 접근 거부 화면으로 이동합니다. 작업별 서비스 권한과 시스템 설정 저장 권한도 실행 시 다시 검사합니다.

비밀번호를 초기화하거나 변경하면 계정의 인증 버전을 증가시킵니다. 이전 버전 쿠키는 다음 HTTP 요청에서 거부하고, 열려 있는 연결도 입력 시 검사와 주기 검사로 로그아웃합니다. 변경된 비밀번호로 다시 로그인해야 합니다. 기존 쿠키에 버전 정보가 없으면 0으로 취급하며, 최초 비밀번호 변경부터 해당 쿠키를 무효화합니다.

사용자와 직책의 편집은 DB 동시성 버전으로 보호합니다. 다른 관리자가 먼저 저장한 정보를 오래된 화면으로 덮어쓸 수 없으며, 충돌하면 입력 내용을 유지하고 최신 정보를 불러오도록 안내합니다. 직책 권한 행의 변경도 해당 직책 버전에 반영합니다.

서버가 검증하는 대상은 다음과 같습니다.

- 메뉴 접근
- Drive 폴더 조회
- 파일 다운로드와 PDF 스트리밍
- 파일 업로드와 폴더 생성
- 파일과 폴더 삭제
- 결재 요청·승인·기록 조회
- Calendar 조회·생성·수정·삭제
- Tasks 조회·생성·수정·삭제·정렬
- 관리자 기능 접근

## Google 데이터

Organization Hub는 연결된 Google 계정의 자료·Calendar·Google Tasks에 접근합니다.  
파일 원본과 Calendar 원본 및 Google Tasks 원본은 Google 계정에 남습니다.

앱 DB에는 운영에 필요한 식별자, Google 매핑, 작성자 정보, 업로드 기록, 일정 삭제 감사 기록, 결재 기록을 저장합니다.  
결재 문서는 제출 시점의 내용과 SHA-256 해시를 앱 DB에 함께 보존합니다. 결재함과 결재 기록의 다운로드는 이 보존본을 사용하며, Google 문서는 PDF로 내보내 보존합니다. 일정 본문 전체는 앱 DB로 복제하지 않습니다.

결재 문서가 포함된 DB와 백업에는 실제 업무 자료가 들어 있으므로 접근 권한과 백업 보관 정책을 적용합니다. 원본이나 Drive 승인본이 나중에 수정되어도 제출 당시 보존본은 유지됩니다.

자료 권한은 기본 자료 위치와 관리자가 연결한 폴더를 기준으로 계산합니다. 요청자가 folder ID나 file ID를 직접 바꿔도 서버 권한 검사를 통과해야 합니다.

## 관리자 권한

시스템 관리자 계정은 제품 설정과 보안 운영을 위한 계정입니다. 업무 결재 후보나 일반 실무 계정으로 사용하지 않는 것을 권장합니다.

관리팀은 별도 업무 팀이며 관리팀 구성원의 권한도 직책과 권한 부여로 제한합니다.  
시스템 설정·Google 연결·권한 관리 같은 고위험 권한은 최소 인원에게만 부여합니다.

## 결재 보안

승인과 반려는 현재 단계와 최신 사용자 권한을 확인하고, DB의 결재 버전으로 동시 처리 충돌을 차단합니다.

최종 결재 접수와 승인본 발행 작업은 같은 DB 트랜잭션으로 저장합니다. 발행할 파일 ID와 작업 식별자는 재시도에서도 유지합니다. Drive 저장 영수증과 내용 체크섬을 확인한 뒤 승인본 ID·완료 상태·업로드 기록을 함께 저장합니다. 저장이 끝나기 전에는 `승인본 저장 중`으로 표시하며 완료 자료에 노출하지 않습니다.

기존 진행 중 결재에는 제출 시점의 보존본이 없으므로 승인을 차단하고 재상신을 안내합니다. 현재 원본을 과거 보존본으로 소급 등록하지 않습니다.

진행 중 결재·반려 결재·완료 결재 기록은 관련자와 권한 보유자만 볼 수 있어야 합니다.

워크플로 변경 후에는 요청자·중간 결재자·최종 결재자·권한 없는 사용자 계정으로 접근 범위를 확인합니다.

## 비밀값

다음 값은 저장소에 커밋하지 않습니다.

- Google OAuth Client Secret
- 운영 SQLite DB
- Data Protection key
- 운영 환경 변수
- Google credential 파일
- 로컬 확인용 데이터와 캡처 산출물

개발 환경은 user secrets를 사용하고 운영 환경은 환경 변수나 배포 플랫폼의 secret 저장소를 사용합니다.

## 운영 체크리스트

- 초기 관리자 비밀번호를 변경했는가
- Google OAuth Secret이 저장소에 없는가
- 각 사용자에게 팀과 직책이 배정되었는가
- 직책 권한 범위가 과도하지 않은가
- 관리팀 권한과 시스템 관리자 권한이 분리되어 있는가
- 다른 팀 자료 직접 접근이 차단되는가
- 관리자 메뉴가 권한 없는 사용자에게 보이지 않는가
- 백업이 최신인가
