# 보안 정책

Organization Hub의 핵심 보안 목표는 사용자가 자신에게 부여된 팀, 직책, 권한 범위 안에서만 자료, 일정, 할 일, 결재 기록을 보거나 변경하게 하는 것입니다.

## 인증

- 직접 회원가입은 허용하지 않습니다.
- 계정은 관리자 화면에서 생성합니다.
- 비밀번호는 해시로 저장합니다.
- 비활성 사용자는 로그인할 수 없습니다.
- 운영 환경에서는 HTTPS가 필수입니다.

## 권한 검증

권한 검사는 화면 표시와 별개로 서버에서 다시 수행합니다.

서버가 검증하는 대상은 다음과 같습니다.

- 메뉴 접근
- Drive 폴더 조회
- 파일 다운로드와 PDF 스트리밍
- 파일 업로드와 폴더 생성
- 파일과 폴더 삭제
- 결재 요청, 승인, 기록 조회
- Calendar 조회, 생성, 수정, 삭제
- Tasks 조회, 생성, 수정, 삭제, 정렬
- 관리자 기능 접근

## Google 데이터

Organization Hub는 연결된 Google 계정의 Drive, Calendar, Tasks에 접근합니다. 앱 DB에는 원본 파일이나 일정 본문 전체를 복제 저장하지 않고, 운영에 필요한 식별자와 상태 정보를 저장합니다.

자료 권한은 공식 루트 폴더와 관리자가 매핑한 폴더를 기준으로 계산합니다. 요청자가 folder ID나 file ID를 직접 바꿔도 서버 권한 검사를 통과해야 합니다.

## 관리자 권한

시스템 관리자 계정은 제품 설정과 보안 운영을 위한 계정입니다. 업무 결재 후보나 일반 실무 계정으로 사용하지 않는 것을 권장합니다.

관리팀은 별도 업무 팀이며, 관리팀 구성원의 권한도 직책과 권한 부여로 제한합니다. 시스템 설정, Google 연결, 권한 관리 같은 고위험 권한은 최소 인원에게만 부여합니다.

## 결재 보안

진행 중 결재, 반려 결재, 완료 결재 기록은 관련자와 권한 보유자만 볼 수 있어야 합니다.

워크플로 변경 후에는 요청자, 중간 결재자, 최종 결재자, 권한 없는 사용자 계정으로 접근 범위를 확인합니다.

## 비밀값

다음 값은 저장소에 커밋하지 않습니다.

- Google OAuth Client Secret
- 운영 SQLite DB
- Data Protection key
- 운영 환경 변수
- Google credential 파일
- 로컬 QA 시드 데이터와 캡처

개발 환경은 user secrets를 사용하고, 운영 환경은 환경 변수나 배포 플랫폼의 secret 저장소를 사용합니다.

## 운영 체크리스트

- 초기 관리자 비밀번호를 변경했는가
- Google OAuth Secret이 저장소에 없는가
- 각 사용자에게 팀과 직책이 배정되었는가
- 직책 권한 범위가 과도하지 않은가
- 관리팀 권한과 시스템 관리자 권한이 분리되어 있는가
- 다른 팀 자료 직접 접근이 차단되는가
- 관리자 메뉴가 권한 없는 사용자에게 보이지 않는가
- 백업이 최신인가
