# 권한 정책

Organization Hub의 운영 권한은 관리자 화면에서 만든 팀, 직책, 권한 부여로 결정됩니다. 팀 이름과 직책 이름은 조직에 맞게 자유롭게 정할 수 있습니다.

## 권한 모델

권한은 `팀 -> 직책 -> 권한 -> 범위` 구조입니다.

예를 들어 `인사팀 / 문서 관리자` 직책에는 팀 자료 조회와 업로드를 소속 팀 범위로 주고, `운영팀 / 운영 책임자` 직책에는 일정 수정과 결재 최종 승인 권한을 모든 팀 범위로 줄 수 있습니다.

한 사용자는 하나의 팀과 직책을 기준으로 로그인합니다. 직책 권한이 설정된 사용자는 그 권한이 우선 적용됩니다.

## 권한 범위

| 범위 | 의미 |
| --- | --- |
| 모든 팀 | 모든 팀과 공용 영역에 적용 |
| 소속 팀 | 사용자가 속한 팀에만 적용 |
| 지정한 팀 | 관리자가 지정한 특정 팀에만 적용 |
| 본인이 만든 항목 | 사용자가 직접 만든 항목에만 적용 |

권한 범위는 넓게 줄수록 운영은 편하지만 보안 위험도 커집니다. 운영자는 필요한 작업 단위로 좁게 부여하고, 임시 권한은 사용 후 회수합니다.

## 주요 권한 영역

- `files.*`: 자료 조회, 업로드, 수정, 삭제, 결재 완료 저장
- `calendar.*`: 일정 조회, 생성, 수정, 삭제, 삭제 기록 조회
- `todos.*`: 할 일 조회, 생성, 수정, 삭제
- `approval.*`: 결재 요청, 승인, 최종 승인, 기록 조회, 워크플로 관리
- `organization.*`: 팀, 직책, 권한, 사용자, 메뉴, Google 연결, 시스템 설정 관리

실제 권한 목록은 관리자 화면의 직책과 권한 설정에서 확인하고 부여합니다.

## 시스템 관리자

시스템 관리자는 첫 설정과 제품 운영을 위한 최고 관리자입니다. 시스템 관리자 직책에는 모든 팀 범위의 관리 권한이 부여됩니다.

시스템 관리자는 조직 구조, 관리팀, 일반 팀, 권한, Google 연결, 결재 경로를 설정합니다. 업무 결재 요청자나 결재 후보는 실제 팀과 직책으로 운영하는 것을 권장합니다.

## 관리팀

관리팀은 시스템 관리자와 다릅니다. 관리팀은 실제 업무 조직의 한 팀이며, 구성원과 직책 권한은 시스템 관리자가 설정합니다.

관리팀에 줄 수 있는 권한 예시는 다음과 같습니다.

- 관리팀 자료 조회/업로드/수정/삭제
- 모든 팀의 업로드 기록 조회
- 사용자 관리
- 일정 삭제 기록 조회
- 결재 기록 조회 또는 최종 승인

관리팀 권한을 운영 관리 목적으로 넓게 줄 수 있지만, 시스템 설정이나 Google 연결 같은 고위험 권한은 최소 인원에게만 부여합니다.

## 메뉴 접근

메뉴 표시도 권한과 연결됩니다. 메뉴가 보이지 않더라도 사용자가 URL을 직접 입력할 수 있으므로, 서버는 파일, 일정, 할 일, 결재 요청마다 다시 권한을 검사합니다.

관리자는 메뉴 보이기 설정에서 메뉴 이름, 정렬, 표시 대상, 접근 수준을 조정할 수 있습니다. 제품 흐름 보호를 위해 일부 핵심 메뉴는 잠겨 있으며, 잠긴 메뉴는 경로나 핵심 접근 수준을 낮출 수 없습니다.

## 결재 권한

결재는 워크플로가 우선입니다.

관리자는 워크플로에서 다음을 설정합니다.

- 어떤 팀 또는 직책이 요청할 수 있는가
- 몇 단계 결재인가
- 각 단계 결재자를 어떻게 찾을 것인가
- 최종 승인 단계가 어디인가

워크플로는 특정 조직의 운영 방식에 맞게 여러 개 만들 수 있습니다. 배포 후에는 요청자, 중간 결재자, 최종 결재자 계정으로 실제 결재 흐름을 확인합니다.
